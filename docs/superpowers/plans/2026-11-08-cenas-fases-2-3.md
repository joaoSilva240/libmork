# Cenas do Mestre — Fases 2 e 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fazer a cena ativa mudar ativamente o escudo (Fase 2 — matriz de comportamento: carrossel/barra de combate/estabelecimentos, auto-`EncounterModal` no Combate, confirmação com 2º plano, indicador) e separar a jukebox por cena (Fase 3 — campo `scene` nas rotas de tracks, protocolo, filtro/abas e tagueamento na UI).

**Architecture:** Consumidores leem a matriz declarativa `modulesForScene` de `src/lib/scenes/sceneConfig.ts` (Fase 1, já commitada) — componentes não conhecem cenas específicas. O `MasterRoster` aplica carrossel/barra; o `CampaignDetail` concentra a confirmação de troca (socket `combatState` + REST de encontros do mundo) e o gate de estabelecimentos; a jukebox filtra por faixa (`scene` = cena ou geral) mantendo faixas em reprodução sempre visíveis.

**Tech Stack:** Next.js 16 App Router, React 19, Drizzle/Postgres, Socket.IO, Vitest + @testing-library/react (jsdom), Tailwind 4, lucide-react, zod já instalado (não obrigatório aqui).

**Spec:** issue #86 — https://github.com/joaoSilva240/libmork/issues/86 (seções "Matriz cena → comportamento", "Requisitos funcionais" 1–4, "Fases" 2 e 3). Fase 1 já mergeada na branch.

```ts
import type { AudioTrack } from "@/lib/audio/jukebox-protocol";
import type { ActiveScene } from "./sceneConfig";

/**
 * Lista visível da jukebox para a cena ativa: faixas da cena + gerais (scene null).
 * Faixas em reprodução permanecem visíveis independentemente da cena (o áudio não para).
 */
export function filterTracksForScene(
  tracks: AudioTrack[],
  activeScene: ActiveScene,
  playingIds: Set<string>,
): AudioTrack[] {
  if (!activeScene) return tracks;
  return tracks.filter((t) => !t.scene || t.scene === activeScene || playingIds.has(t.id));
}
```
